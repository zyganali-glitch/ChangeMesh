## 📝 1. Deep-Dive Technical Build Article (Ready for Medium / Dev.to)

### Title: Building ChangeMesh: Rehearsing Breaking Enterprise Changes with Gemini 3.6 Flash & Google Cloud

**Subtitle:** *How we engineered a proof-carrying multi-agent fleet on Cloud Run and Firestore to eliminate migration outages.*

#### Introduction
When AI coding agents are given real database credentials or CI/CD access, they move fast—and break things faster. A single hallucinated `DROP COLUMN` or uncoordinated API parameter change can cause significant operational downtime.

We built **ChangeMesh** for the Google Gemini Sprint Hackathon (Fortified Enterprise Fleet category) to solve this fundamental enterprise trust problem. Instead of letting agents execute unverified changes directly, ChangeMesh rehearses every distributed schema and API migration inside **ShadowLab**—a synthetic data simulation engine—before escalating a single compressed decision packet to humans.

#### Key Architectural Invariants
1. **The 4-Lane Authority Model:** Four distinct lanes (Deterministic Code, Gemini Semantic Judgment, Organizational Policy, and Human Authority) ensure model semantic judgment can never overwrite deterministic code facts or organizational policy rules.
2. **Zero-Custody VPC Boundary:** Designed a target 4-plane decoupled architecture (Control, Adapter, Policy Pack, Customer Data planes) keeping customer schemas and data strictly within private VPC networks.
3. **Pure Serverless Scale-to-Zero:** ChangeMesh runs natively on Google Cloud Run (`europe-west3`) with Firestore Native OCC CAS persistence and Pub/Sub eventing, configured with `min_instances=0` scale-to-zero serverless architecture.
4. **Zero Frontend Build Dependencies:** We eliminated all Node.js/npm dependencies in favor of standard Python and vanilla ES6/CSS3.
