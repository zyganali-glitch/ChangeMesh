## 2. Two-Tier Integration Architecture & Cost Isolation

ChangeMesh enforces strict boundaries between deterministic integration testing and live cloud provider writes:

```mermaid
flowchart TD
    subgraph Tier A: Cost-Isolated Integration Suite (Default / CI)
        A1[ADK Agents & Orchestrator] -->|Process-Local Dispatch| A2[Deterministic Router & Coordinator]
        A3[Gemini Structured Parser] -->|Strict JSON Schema & Privacy Gate| A4[Model Boundaries & Audit]
        A5[Pub/Sub Wire & Consumers] -->|Byte Serialization & Delivery State| A6[Dead Letter & Causal DAG]
        A7[Firestore State Repository] -->|In-Memory OCC CAS & Key Manager| A8[Tenant Isolation & Teardown]
        A9[Bounded GitHub Adapter] -->|Mock Transport & 5-Point Reconcile| A10[Intent Markers & Receipts]
        A11[Managed Adapters] -->|Honest Status & Local Fallback| A12[Gateway & Security Registries]
    end

    subgraph Tier B: Live Cloud Mutation Danger Path
        B1[Live Google Pub/Sub]
        B2[Live Google Cloud Firestore]
        B3[Live Google Cloud Model Armor]
        B4[Live GitHub REST API]
    end

    Tier A -.->|Isolated / Zero External Cost| Tier B
```

### Cost Isolation Boundary Properties:
1. **Zero Provider Spend:** No test in `tests/test_p25_02_integration_matrix.py` or the canonical test suite invokes live billable Google Cloud APIs, Gemini tokens, or GitHub mutating endpoints.
2. **Deterministic Reproducibility:** All fixtures, memory state repositories, delivery trackers, and mock transports run entirely in-process without network flakes or external credentials.
3. **Strict Mode Enforcement:** `BoundedGitHubAdapter` and `GooglePubSubConsumer` fail closed if live mode is requested without explicit authorization, valid state repositories, or credentials.

## 3. Resolution of Historical Pytest Collection Debt

Prior to P-25.02, running `uv run pytest` across the entire repository resulted in collection errors on `tests/test_gcp_access.py` when Google Cloud Application Default Credentials were not present in the local shell environment:

### Root Cause:
`tests/test_gcp_access.py` contained test functions prefixed with `test_` (`test_firestore_`, `test_pubsub_publish`, `test_gemini_api`) intended as interactive live smoke tests. Pytest automatically collected these during full-suite runs, causing `DefaultCredentialsError` during test collection.

### Resolution:
1. Set `__test__ = False` on the module to prevent automated discovery by pytest.
2. Renamed functions to `check_firestore_connectivity`, `check_pubsub_publish`, and `check_gemini_api`.
3. Preserved file integrity for manual, explicit live smoke verification when credentials are intentionally provided.
4. **Outcome:** `uv run pytest` now passes 100% cleanly across all 1594 tests with 0 collection errors.
