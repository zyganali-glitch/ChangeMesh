## 4. Idempotency Ownership Map

To ensure strict zero-new-debt and prevent conflicting or overlapping retry and idempotency implementations, the architectural layers are strictly delineated:

```
[Layer 1: P-09 Wire Message Identity]
  - EventEnvelope headers: event_id, idempotency_key, causation_id, correlation_id
  - Pure wire serialization and envelope validation (events/wire.py)
       │
       ▼
[Layer 2: P-09 Transport Duplicate Delivery Protection]
  - InMemoryDeliveryState (events/delivery_state.py)
  - Process-local in-memory seen_events deduplication per consumer session
  - Transport identity: transport="LOCAL" vs Google Pub/Sub transport
       │
       ▼
[Layer 3: P-09 Transport Dead-Letter Replay Idempotency]
  - ProcessLocalDeadLetterState (events/retry.py)
  - Thread-safe bounded FIFO cache for immediate transport-level terminal failure handoff replay
  - Single local retry owner: execute_with_retry()
       │
       ▼
[Layer 4: P-10 Durable Workflow-Step & External-Write Reservation (FUTURE)]
  - Durable workflow state and step idempotency persistence (src/orchestrator/firestore_saga.py)
  - Durable cross-session atomic reservation preventing duplicate step dispatch and writes across process restarts
  - State machine lifecycle persistence & optimistic concurrency version checks
       │
       ▼
[Layer 5: P-19 Actual External Write Execution (FUTURE)]
  - Release Steward (src/agents/release_steward.py)
  - Performs GitHub draft PR creation with verify-then-skip idempotency and writeback receipts
       │
       ▼
[Layer 6: P-20 End-to-End Saga Orchestration & Recovery (FUTURE)]
  - Change Orchestrator (src/agents/change_orchestrator.py)
  - Multi-agent saga workflow execution, resume from Firestore checkpoints, compensation dispatch
```

### Invariants:
1. **Zero Competing Retry Owners:** `execute_with_retry()` in P-09 remains the *only* local retry owner. P-10 does not create a second retry engine; it provides durable state persistence for saga steps.
2. **Distinct Lifecycles:** P-09 in-memory delivery state is process-local and transport-scoped. P-10 idempotency reservations are durable, transactional, and scoped to the workflow execution.
3. **No Terminal Authority Fabrication:** In P-09, P-10, and throughout the entire lifecycle, retry exhaustion or dead-letter state strictly maintains `TerminalFailureHandoff.human_authority_required = False`.

## 8. Security and Privacy Persistence Constraints

1. **Zero Secret Persistence:** Credentials, private keys, API tokens, connection strings, and service account keys must NEVER be written to Firestore documents or serialized in saga state payloads.
2. **References & Hashes Over Blobs:** Store lightweight identifiers (`change_id`, `run_id`, `passport_id`), artifact paths, and SHA-256 hashes rather than giant raw code blobs or proprietary customer datasets.
3. **Explicit Tenancy Isolation:** Tenancy isolation must be explicit and fail closed. Cross-tenant access, cross-tenant query execution, and unauthenticated namespace leakage must be prevented. The exact tenant identifier and Firestore collection/document hierarchy are P-10.01 design decisions.
4. **Schema Validation & Fail-Closed Deserialization:** State loaded from Firestore must pass strict Pydantic schema validation with `extra="forbid"`. Corrupted, tampered, or unknown schema versions must fail closed immediately.
5. **No Evidence Tampering:** Persisted saga state is deterministic operational execution data. It cannot overwrite or mutate locked deterministic evidence states in the Evidence Ledger.
