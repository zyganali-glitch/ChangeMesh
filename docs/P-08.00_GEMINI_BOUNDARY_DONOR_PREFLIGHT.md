## 3. Prompt / Input Boundary Memo

> **Scope:** Defines requirements for later Gemini calls (P-08.01, P-08.03). Does NOT implement them.

### 3.1 Field-Level Input Minimization

**INP-01:** Only task-minimal allowlisted fields may reach the model. A Gemini prompt must contain only the fields explicitly required for the semantic task. No evidence pack, no complete change record, no full blast-radius graph is sent wholesale.

**INP-02:** Deterministic facts are externally locked before the model sees them. The model receives facts as read-only context but cannot rewrite their execution state, evidence mode, hash, or exit code.

**INP-03:** Model receives facts but cannot rewrite their execution state. Following CCT-EVID-001 invariant: the model's judgment output is validated against locked facts. Any attempt to promote `NOT_RUN`, `BLOCKED`, `SIMULATED`, or `FAIL` to `PASS` is rejected.

### 3.2 Credential Boundary

**INP-04:** Credentials NEVER reach prompts. Following `docs/THREAT_MODEL.md` TB-08 and `AGENT_ENVIRONMENT_AND_API.md`: API keys, tokens, ADC material, cookies, service-account JSON, GitHub tokens, and all credential material must be stripped before any text reaches the Gemini API. The ZK-PRIV-001 blocking pattern approach (regex-based pre-scan) informs this, but ChangeMesh must implement it as a deterministic gate, not just a pattern scanner.

**INP-05:** Secret/PII handling before model boundary. Following ZK-PRIV-001: text is scanned for private keys, API keys, JWTs, bearer tokens, connection strings, and production data markers BEFORE entering the prompt. Blockers cause fail-closed; warnings are logged.

### 3.3 Untrusted Content Boundary

**INP-06:** External/untrusted text remains data and cannot become system authority. Following `docs/THREAT_MODEL.md` §9: GitHub repository content, metadata graph results, tool output, and user-supplied text are strictly data. They cannot modify system prompts, override policy, change authority classes, or become organizational policy.

**INP-07:** Synthetic vs real input is explicit. Following `docs/EVIDENCE_BOUNDARY.md`: every input to the model must carry explicit execution mode provenance (`FIXTURE`, `SIMULATION`, `RECORDED_CLOUD`, `LIVE_WRITE`). Synthetic demo fixtures must not be passed as production evidence.

### 3.4 Provenance and Authority

**INP-08:** Exact agent/change provenance remains available where required. Following P-07.05: agent `agent_id` and `agent_revision` are available for inclusion in prompts where provenance is relevant (e.g., evidence auditor knowing which agent produced evidence).

**INP-09:** Authority lane of every model-produced conclusion is `GEMINI_SEMANTIC_JUDGMENT` only. Following `docs/AUTHORITY_MAP.md`: model output never acquires `DETERMINISTIC_CODE`, `ORGANIZATIONAL_POLICY`, or `HUMAN_AUTHORITY` status.

**INP-10:** Model uncertainty cannot create authorization or `HUMAN_AUTHORITY`. Following architecture invariant 5.6: when Gemini is uncertain, the system uses validation, retry, or fail-closed — never manufacturing a human-authority slot.

### 3.5 Anti-Leakage

**INP-11:** No hidden prompt fallback. If the primary Gemini model is unavailable, the system fails closed. No silent fallback to another model, cached response, or hardcoded default.

**INP-12:** No silent provider fallback. The system does not silently switch from Gemini to another provider. Provider identity is explicit in all evidence records.

## 4. Output Boundary Memo

> **Scope:** Defines requirements for later structured reasoning/output work (P-08.02). Does NOT implement them.

### 4.1 Untrusted Model Output

**OUT-01:** Model output is untrusted until deterministic schema validation. Following ZK-VALID-001 invariant: every Gemini structured output must pass a Pydantic schema validator before consumption. The schema must be defined by ChangeMesh domain contracts, not by the model.

**OUT-02:** Missing required fields fail closed. If a required schema field is absent from the model's output, the entire response is rejected. No default-filling is permitted.

**OUT-03:** Extra forbidden fields fail closed. If the model's output contains fields not in the expected schema, the response is rejected (Pydantic `extra="forbid"` pattern already established in P-05 contracts).

**OUT-04:** Wrong types fail closed. If a field has the wrong type (e.g., string where integer expected), the response is rejected.

**OUT-05:** Malformed output is not silently coerced. No auto-repair, no "closest valid value" substitution, no silent type conversion.

**OUT-06:** Unsafe endpoint/path/action values fail. Path traversal (`../`), absolute paths outside scope, unknown action types, and unregistered endpoints are rejected deterministically.

**OUT-07:** Provider-specific hidden fields are forbidden. The model's response must not contain Google-internal, SDK-internal, or debugging fields that leak into domain contracts.

### 4.2 Semantic Output Cannot Overwrite Facts

**OUT-08:** Semantic output cannot overwrite deterministic `EvidenceState`, command result, hash, execution mode, authority decision, or approval fact. Following CCT-EVID-001 and CCT-SEM-001: `validateModelCannotOverwriteFact` pattern.

**OUT-09:** No expected-answer leakage for blind semantic audit. Following CCT-SEM-001: when the Evidence Auditor (Gemini) assesses evidence, the expected result is never included in the prompt. The model sees only evidence and mission.

**OUT-10:** Citations/evidence references must remain distinguishable from model prose. The model's output must structurally separate citations (pointers to specific evidence) from generated explanations.

|---|---|---|---|
| **Command ran or did not run** | `DETERMINISTIC_CODE` | Model may comment, but `command_ran` fact is immutable | **NO** |

**Model disagreement cannot transfer a fact between lanes:**

| Scenario | Deterministic Fact | Model Claim | Resolution |
|---|---|---|---|
