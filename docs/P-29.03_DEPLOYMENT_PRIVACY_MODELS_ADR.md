## 1. Context & Problem Statement

Enterprise customers have varying security, data sovereignty, and compliance requirements regarding schema inspection, code access, and database migration execution. A one-size-fits-all SaaS architecture is unacceptable for regulated enterprises.

---

## 2. Decision: 3-Tier Deployment & Privacy Spectrum

ChangeMesh adopts a 3-tier deployment model catering to startups, mid-market SaaS, and regulated enterprise environments:

| Attribute | Model A: Multi-Tenant Hosted SaaS | Model B: Hybrid VPC Runner (Enterprise Default) | Model C: Fully Private Air-Gapped |
|---|---|---|---|
| **Control Plane** | Managed Cloud Run (GCP) | Managed Cloud Run (GCP) | Customer VPC (GKE / GDC) |
| **Execution Runner** | Ephemeral Cloud Run container | Customer-Hosted Sidecar (Customer VPC) | Customer VPC Sidecar |
| **Database Access** | Public IP with mTLS / IP allowlist | Internal VPC Private IP (Zero Ingress) | Internal VPC Private IP |
| **Model Authority** | Vertex AI (`gemini-3.6-flash`) | Vertex AI / Customer Private Endpoint | Google Distributed Cloud / Private Endpoint |
| **Data Custody** | Zero-retention scrubbed metadata | Zero custody (Hashes & digests only) | 100% On-Premise / Sovereign |
| **Compliance Tier** | SOC 2 Type II | SOC 2, HIPAA, ISO 27001 | FedRAMP High, PCI-DSS, Air-Gapped |

---

## 3. Explicit Security Boundaries & Tradeoffs

- **Zero Ingress to Customer VPC in Model B:** The customer-hosted runner initiates outbound gRPC/WebSocket connections to the ChangeMesh control plane; no inbound firewall ports are opened into customer infrastructure.
- **Payload Minimization:** Wire protocols carry only normalized diff ASTs, evidence digests, and assertion results.
- **Fail-Closed Isolation:** If runner connectivity drops, the saga state repository holds in `BLOCKED` status without making partial speculative commits.
