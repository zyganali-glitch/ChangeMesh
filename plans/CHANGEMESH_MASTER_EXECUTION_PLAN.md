## 0. Frozen mutual agreement

The owner and planning assistant have already agreed on the product. No generic Phase-0 interview is permitted.

### Product

**ChangeMesh — The Enterprise Change Rehearsal and Execution Fleet**

### Core promise

ChangeMesh enables enterprise agent fleets to work autonomously for hours or weeks, while escalating only the smallest irreducible set of human authority decisions.

### Product loop

**Discover → Qualify → Rehearse → Ground → Authorize → Execute → Prove → Certify**

### Competition contract

Based on the supplied competition page, project must use Gemini 3.5+ via Gemini API/Vertex AI; use at least one Google agent framework; use at least one Google Cloud infrastructure service; build/deploy a next-generation autonomous agent beyond chat; prove Google Cloud backend; submit repository, description, architecture diagram, and approximately four-minute demo; and fit Fortified Enterprise Fleet. Official rules remain binding and are reverified in P-01.

### Mandatory product properties

- autonomous by default;
- human-on-the-loop;
- Approval Compression;
- ADK runtime;
- real Gemini runtime call;
- real Google Cloud deployment;
- asynchronous/restart-safe workflow;
- trusted cross-session memory;
- Capability Passport;
- ShadowLab rehearsal;
- Reversibility Gate;
- evidence ledger/Change Evidence Passport;
- real reversible GitHub action;
- explicit fixture/simulation/real boundaries;
- credible independent product path.

### Non-goals

No automatic production merge/deploy, real customer data, formal verification, universal agent marketplace, generic workflow builder, broad multi-cloud support, unsupported security/compliance guarantee, or bulk copy of donor repos.

# P-Ω — Continuous Whole-Repository Integrity and Live-Docs Sync

**Status:** `ALWAYS_ACTIVE`  
**This phase never closes before the final frozen release. It runs after every micro-task.**

## P-Ω.01 — Diff and scope audit

Compare changed files with active allowlist. Detect accidental generated files, secrets, caches, unrelated formatting, truncation, dead/duplicate code, stale imports. Any unrelated change blocks closure.

## P-Ω.02 — Implementation and test parity

Verify changed behavior has relevant test or explicit NOT_RUN rationale. Tests must assert mission behavior, not only exit code/file existence. Re-run affected tests after config/doc changes when needed.

## P-Ω.03 — Architecture parity

Compare modules, dependency directions, schemas, states, agents, cloud services, trust boundaries with architecture memory, `docs/ARCHITECTURE.md`, and README. Update docs or reopen task.

## P-Ω.04 — Plan and repository parity

Confirm statuses match files/evidence; no completed feature remains planned and no planned feature appears complete; discovered work registered; dependencies respected.

## P-Ω.05 — README and setup parity

Verify feature list, status, commands, requirements, architecture, limitations, links. Never publish setup before clean-checkout verification. Synchronize English/Turkish facts.

## P-Ω.06 — Memory and handoff sync

Add lessons; update architecture/environment; add ADRs; update handoff with exact next task, blockers, evidence, current claims.

## P-Ω.07 — Competition claim parity

Search README, Judge Start, Judging Map, Devpost, demo, screenshots, submission manifest, build disclosure for duplicated claims. Every success maps current evidence. Update rules/deadlines only from official sources.

## P-Ω.08 — Demo and UI parity

Verify script uses actual buttons, states, timing, data, workflow. Screenshots from current/frozen revision. UI cannot animate invented work.

## P-Ω.09 — Triple-sync parity

When remote/deployed state changes, record/compare local commit, GitHub branch/tag/release, Google Cloud revision/image/config. Mismatch is WARN or BLOCKED.

## P-Ω.10 — Contradiction and stale-reference search

Search for old product names, obsolete paths, old model IDs, wrong regions/statuses, stale screenshots, inconsistent agent counts, unsupported production-ready/secure/complete/live language, Phase-0 instructions, and repeated approvals violating autonomy.

## P-Ω.11 — Closure record

Append files changed, tests, evidence states, docs updated, contradictions fixed, unresolved WARN/NOT_RUN, Git state, next task. Task cannot be DONE until P-Ω=PASS.
